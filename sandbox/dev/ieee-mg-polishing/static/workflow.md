# ieee-mg-polishing 标准润色流程

> 基于课题组论文语言特征的润色工作流。
> **v1.2.0**：light/moderate/deep 操作化边界；图描述时态修正；判断边界。

## 润色工作流

### 第一步：需求分析
- 明确用户要求的润色范围（章节/全文）
- 确认润色深度（light/moderate/deep）
- 识别论文的技术领域（RIS/NOMA/STARS/FL等）

### 第二步：结构检查
- 检查该章节是否包含课题组标准结构中的必含要素（对照 section-architecture.md 的 ✅/💡 分级）
- Abstract：5要素是否完整（背景→问题→方法→结果→意义；B/E 为可选）
- Introduction：5层架构是否完整
- Results：是否有参数表（TABLE I/II）、基准方案（≥1）、三段式分析
- **结构缺失 ≠ 润色必须补齐**：结构性问题应提示用户，由用户决定是否补写（补写属于写作任务）

### 第三步：语言润色
按照以下优先级逐层处理：
1. **语法层**：主谓一致、时态、冠词、介词（对照 common-errors.md 语料实测错误表）
2. **用词层**：术语标准化、动词选择、形容词使用
3. **句式层**：句子长度（15-30词）、从句结构、主动/被动平衡
4. **逻辑层**：过渡词使用、指代清晰度、段落主题一致性

### 第四步：润色深度操作化边界（v1.2.0）

| 深度 | ✅ 可以改 | ❌ 不可以改 |
|------|----------|-----------|
| **Light** | 语法/拼写/标点错误；缩略形式（doesn't→does not）；缺冠词；明显时态错误；术语定义缺失 | 句式结构；用词替换；内容增删；段落重排 |
| **Moderate** | Light 全部 + 句式重组（合并/拆分句子）；用词升级（superior 替代 good 类）；过渡词优化；冗余精简 | 新增技术内容；删除技术信息；调整章节结构；修改数据/公式 |
| **Deep** | Moderate 全部 + 段落级重写（保留核心信息）；结构微调（段落内顺序）；风格统一 | 技术事实；数据/公式/引用；**新增内容（须询问用户）** |

**决策树标注一致性**：各章节决策树中的操作标注了适用深度（light/moderate/deep），执行时遵守上表边界；若章节决策树标注与上表冲突，以上表为准。

### 第五步：格式检查
- 数学符号是否符合 IEEE 规范（斜体/粗体/花体）
- 引用格式是否为 IEEE 编号格式 [1], [2]-[5]
- 图表引用是否统一为 "Fig. X" / "Table X"
- 缩略语是否在首次使用时正确定义

### 第六步：输出交付
- 提供润色后的完整文本
- 可选：修改说明摘要（主要修改类型和数量）
- 可选：重点修改标注（对关键修改给出简短理由）
- **涉及新增内容的修改**：在修改说明摘要中标注"新增内容，待确认"

## 润色深度说明（对应 manifest polish_level 轴）
| 深度 | 修改范围 | 适用场景 |
|------|----------|----------|
| Light | 语法错误+拼写+标点 | 投稿前快速检查 |
| Moderate | 语法+句式优化+用词改进 | 审稿意见回复后修改 |
| Deep | 全面语言和风格优化 | 非英语母语作者稿件、重投前准备 |

## 判断边界（v1.2.0 新增）
- **新增内容授权**：决策树中所有"补充/添加"分支，仅在用户已提供相关内容时补全表达；凭空新增先询问用户；
- **语料合法变体保护**：不强制改写语料实证的合法表达（"In this paper, we investigated"、"Fig. X plots"、"-" 项目符号列表）；
- **图描述时态**：图描述一律现在时（"Fig. X plots..."）；仿真过程描述过去时可选。
