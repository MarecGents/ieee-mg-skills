# System Model 审核清单

> **⚠ 口径声明（v1.2.0）**：语料库无 System Model 章节正文（All Paper Title.md 仅含 Abstract/Introduction/Numerical Results/Conclusion 四部分）。本清单第 1/4/5/8/9/10 项基于**外部通用知识（IEEE 惯例）**，证据强度低于其他章节；审核报告中此类问题标注"存疑/通用规范"，不作为硬性判错依据。第 2/3/6/7 项有 style-profile 数学规范支撑。

- [ ] 1. 系统场景是否清晰描述（坐标/拓扑/假设）⚠ 通用规范
- [ ] 2. 所有数学符号首次使用时是否定义（style-profile §6 数学规范）
- [ ] 3. 变量是否斜体 $x$，向量是否粗体 $\mathbf{x}$（style-profile §6）
- [ ] 4. 信道模型是否明确命名（Rician/Nakagami/Shadowed-Rician/Rayleigh）⚠ 通用规范（信道类型语料可溯源，但"必须命名"为通用惯例）
- [ ] 5. 优化问题是否完整（目标函数 + 约束条件）⚠ 通用规范（如适用）
- [ ] 6. 公式后是否有标点（, 或 .）（style-profile §6）
- [ ] 7. 公式编号是否连续（style-profile §6）
- [ ] 8. 算法步骤是否清晰（伪代码）⚠ 通用规范（如适用）
- [ ] 9. 是否提供复杂度分析 ⚠ 通用规范（💡 建议项）
- [ ] 10. 是否有假设声明段落 ⚠ 通用规范

## 常见致命问题（全映射；⚠ 项判定标准给出正反示例）
| 问题 | 触发检查项 | 严重性 | 判定标准 |
|------|-----------|:------:|----------|
| 符号未定义 | #2 | 🔴 | 符号在首次使用时无定义（正例 "y_i = h_i x + n_i, where h_i denotes..."；反例 "y = hx + n" 无 where 说明） |
| 变量格式不规范 | #3 | 🟡 | 数学变量未用斜体/粗体（纯文本稿件除外，标注"待排版"） |
| 信道模型未命名 | #4 | 🟡 | 写了 "fading channels" 但未指明类型（Rician/Nakagami/...）⚠ 通用规范 |
| 优化问题不完整 | #5 | 🔴 | 有目标函数但无约束，或反之（如适用时）⚠ 通用规范 |
| 无复杂度分析 | #9 | 🟢 | 提供算法但无复杂度讨论（💡 建议项） |
| 无假设声明 | #10 | 🟡 | 全文无任何假设说明（如 CSI 假设、信道独立性假设）⚠ 通用规范 |
