# 审核工作流

> **v1.2.0**：新增证据链规范；量化判定引用 quantitative-baseline.md；报告条目强制"依据"字段。

## 标准审核流程

### Step 1：全文通读（或目标章节通读）
快速通读，建立整体感知：
- 识别技术主题和研究方向
- 评估整体结构完整性
- 标记明显的结构缺失
- **确定审核范围（scope）、报告语言（language）、严格度（severity）**

### Step 2：逐章审核
按照各 check-*.md 清单逐章检查：

```
check-abstract.md      → 检查摘要的5要素（B/E 可选）、编号结果、词数（85-280）、开头模式
check-introduction.md  → 检查引言的5层架构、贡献列表、研究空白（约 57% 用 To the best）、过渡手法
check-motivation.md    → 检查承上启下开头、空白句式、贡献点（≥3，动词多样性 ≥3 类）
check-system-model.md  → 检查模型符号一致性和逻辑链（⚠ 外部通用知识，证据强度低）
check-results.md       → 检查参数表（TABLE I/II）、基准（≥1）、四步分析（引入→观察→解释→对比）、图描述现在时
check-conclusion.md    → 检查结论四型开头、单段、词数（80-200）、无新引用、未来工作（约 48%）
```

**证据链规范（每条问题必须三步走）**：
1. **问题**：具体缺陷描述；
2. **证据**：原文引用（精确到句。**句号编号规则**：以句号/问号/感叹号为句界切分，分号不算；引用编号列表（如 [1]-[17]）整体计 1 句；公式行与图表标题不计句）；
3. **依据**：触发的 check 项 + 语料模式/quantitative-baseline 数值（正向命中式，如 "check-abstract #12：we 密度 8.2/千词，超 baseline §3 的 6-8 区间"）。

### Step 3：全局检查
- 术语一致性检查（对照 share/terminology.md）
- 缩略语规范检查
- 引用格式统一性
- 时态全局一致性（图描述现在时）

### Step 4：生成报告
按照 `report-template.md` 格式输出（按 scope 裁剪章节分布表；每条问题含"依据"字段）：

```
## Review Report — [论文标题]
### 总体评价
[风格符合度等级：高/中/低（定性为主，可附量化证据）] [总体描述]

### 问题列表（按严重性排序）
#### 问题 #N [严重性] [类别]
**位置**: [章节], 第X句
**原文**: ...
**问题**: ...
**依据**: [check 项 #N / quantitative-baseline §X 数值]
**建议**: ...

### 统计摘要
| 严重性 | 数量 |
|--------|:----:|
| 🔴 严重 | X |
| 🟡 中等 | X |
| 🟢 建议 | X |
| ⚠ 存疑/需人工复核 | X |
```

### Step 5：输出前检查
- [ ] 每条问题是否含"依据"字段
- [ ] 量化判定是否引用 quantitative-baseline.md（未自行设区间）
- [ ] 是否误判语料合法变体（见 core.md 原则 6）
- [ ] 是否按 scope 裁剪了章节分布表（单章时全局检查仅针对该章）
- [ ] 是否按 severity 过滤了问题级别（统计表只统计输出级别 + ⚠ 行；⚠ 始终列出）
- [ ] 范围外技术问题是否单独标注（不纳入风格统计）
