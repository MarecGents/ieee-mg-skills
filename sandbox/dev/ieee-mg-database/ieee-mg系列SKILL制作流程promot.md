# ieee-mg 系列 SKILL 制作流程 Prompt（v2.0 — 两轮蒸馏框架）

## 角色与目标

你是一名**学术写作风格分析专家**、**AI 技能工程师**和**技能质量审计员**。
你的任务是：基于课题组 **21 篇通信领域顶级会议/期刊论文**的章节语料（已按结构拆分为独立文件），以及**已发布的 ieee-mg 四技能体系**（ieee-mg-share / ieee-mg-writing / ieee-mg-polishing / ieee-mg-reviewer，v1.1.0），执行**两轮深度蒸馏**：

- **第一轮蒸馏（已完成，框架保留）**：从原始语料蒸馏出分章节写作规范与技能初版；
- **第二轮蒸馏（本轮核心）**：对已有技能做「语料实测 vs 现状」差距诊断，修正事实性错误、补齐缺失维度（约束分级、思考深度、判断边界、灵活程度）、查漏补缺，产出 v1.2.0 升级包。

## 输入说明

### 语料库（只读，不得修改原始文本，可做分词/标注/频率统计/模式匹配）
- `Abstract.md` —— 21 篇摘要
- `Introduction.md` —— 21 篇引言（含各子节）
- `Motivation and Contribution.md` —— 20 篇动机与贡献（一篇可能空白）
- `Numerical Result.md` —— 21 篇数值/仿真结果
- `Conclusion.md` —— 21 篇结论
- `All Paper Title.md` —— 21 篇完整论文（仅含 Abstract / Introduction / Numerical Results / Conclusion 四部分；**不含 System Model 章节正文**，该章节优化只能基于组织句与动机中的间接线索，禁止编造语料数据）

### 现有技能体系（本轮优化对象）
- `ieee-mg-share`（共享层：style-profile / terminology / expression-bank / logic-connectors / section-architecture / common-errors / paragraph-rhythm / quantitative-baseline）
- `ieee-mg-writing`（core / workflow / 6 个 section-*.md）
- `ieee-mg-polishing`（core / workflow / 6 个 section-*.md）
- `ieee-mg-reviewer`（core / workflow / report-template / 6 个 check-*.md）

### 开发与发布约定
- 优化在 **sandbox/dev/ 下的技能副本**上进行，`skills/` 下的已发布版本在质量审查通过前不得改动；
- 版本号统一升级（如 1.1.0 → 1.2.0），同步 manifest.yaml / skills.sh.json / README.md。

## 质量维度定义（所有优化动作的评判标准）

| 维度 | 定义 | 验收标准 |
|------|------|----------|
| **约束程度** | 规则的强制力分级 | 每条规则必须标注：✅ 硬约束（必须/禁止，可客观判定）/ 💡 软约束（建议，附频率证据）；必须有检查清单或量化标准，禁止不可判定的空泛表述 |
| **思考深度** | 规则使用的推理结构 | 复杂判断必须有决策树/分支逻辑/推理链（如"若 A 且 B → 做 C"）；低频模式必须标注频率与适用条件 |
| **判断边界** | 规则的适用范围与触发条件 | 必须写明：何时该做/不该做、何时询问用户、何时停止、数据缺失时如何降级、证据不足时如何标注 |
| **灵活程度** | 对不同输入的自适应 | 必须覆盖 paper_type（journal/conf/mag）、章节变体、技术场景（NOMA/RIS/STARS/FL/卫星/保密/隐蔽通信）的适配分支 |
| **可溯源性（反幻觉）** | 每条规则的证据链 | 统计声明必须可回溯到语料（给出样本范围与计数）；"语料中不存在 X"类断言必须先 grep 验证；语料无依据的内容必须显式标注来源等级 |
| **交叉一致性** | 四技能间的引用同步 | share 与 writing/polishing/reviewer 使用同一术语、句式、数值口径；同一事实禁止在两个文件中出现矛盾表述 |

### 来源等级标注（每条规则必须归属其一）
1. **语料实测**：可给出语料原文/计数证据，格式如「语料 16/21 篇（76%）使用 we」；
2. **课题组规范**：语料无直接统计但符合 IEEE 惯例或课题组约定；若语料存在反例（如缩略形式偶现），必须注明「语料偶见反例，polishing 需纠正」；
3. **外部通用知识**：与语料无关的领域通用知识（如 System Model 章节的 IEEE 写作惯例），必须显式标注「非语料蒸馏」，严禁伪装成语料特征。

## 第一轮蒸馏流程（语料 → 技能初版；v1.0 已执行，流程保留）

### 阶段 0：环境准备与语料加载
- 建立分章节语料库，记录每篇论文标题、字数、段落数、句子数等统计，输出语料概览报告。

### 阶段 1：全局风格特征提取
- 学术正式度、客观性、句式复杂度、词汇偏好、逻辑连接词、时态分布的定量描述，输出全局风格画像。

### 阶段 2：分章节深度结构分析与模板抽取
- 逐章节识别结构模板、句式库、长度约束、逻辑连接方式，输出每章节的 Structural_Template。

### 阶段 3：约束规范抽取
- 提炼硬性约束（必须遵守）与软性建议（最好遵守），每条注明语料来源（至少引用 3 篇论文实例）。

### 阶段 4：生成可执行的 AI SKILL
- 整合为结构化 SKILL 定义（角色设定、全局风格指令、分章节写作规则、交互流程、示例）。

### 阶段 5：迭代验证与优化（可选循环）
- 生成样例与语料对比（BLEU/结构相似度/人工评估），偏差反馈回阶段 2-3 修正。

## 第二轮蒸馏流程（诊断 → 复核 → 优化 → 验证 → 发布；本轮核心）

### 阶段 A：现状诊断
对目标技能**每个文件**执行：

1. **反幻觉扫描**：逐条提取文件中的统计声明（占比/频次/星级/存在性断言）与规则示例（错误案例、句式模板），标注为「待核验」；
2. **维度缺口扫描**：对照质量维度定义，检查文件缺失的维度（约束分级、判断边界、思考深度、灵活度）；
3. **查漏补缺扫描**：对照语料，找出语料高频但技能未覆盖的模式（句式、术语、结构变体）；
4. **交叉一致性扫描**：与共享层其他文件比对，找出同源冲突（同一数据两个数值、同一句式两种判断）。

**输出**：`差距诊断清单.md`，按 技能 × 文件 组织，每条问题含：位置 | 问题类型（反幻觉/约束分级/思考深度/判断边界/灵活度/查漏补缺/交叉冲突） | 具体描述 | 建议修复方向 | 优先级（P0 事实性错误 / P1 统计修正 / P2 约束与边界 / P3 查漏补缺与灵活度）。

### 阶段 B：语料实测复核
对诊断清单中每条「待核验」声明回语料验证：

1. **计数规范**：统计必须注明口径——范围（哪几个文件/哪些章节）、方法（grep 行级/词级计数、逐篇人工核验）、样本量（N/21 篇）；禁止无口径的「约 XX%」；
2. **断言复核**：「语料中不存在 X」「100% 使用」「语料主流」类断言必须实际检索，出现反例即降级为软约束并注明反例；
3. **缺失章节处理**：System Model 等语料缺失章节，优化只允许基于可溯源线索（如 Organization 段落、Motivation 中的模型特征）做保守增补，所有内容标注「外部通用知识，非语料蒸馏」；禁止为缺失章节编造「语料实测」统计；
4. **错误案例核验**：polishing/common-errors 中的每个错误案例必须能在语料中找到真实实例；找不到的删除，找到但未收录的补充（附语料位置）。

**输出**：`复核记录.md`，每条记录「声明 → 复核方法 → 结果（证实/证伪/无据）→ 修正建议」。

### 阶段 C：差距优化（按优先级执行）
按 P0 → P1 → P2 → P3 顺序逐文件修改：

- **P0 事实性错误**：与语料直接矛盾的规则（词数区间、时态规则、编号格式、存在性断言）立即修正，并同步所有引用该错误数据的文件（含共享层），杜绝错误传播；
- **P1 统计修正**：占比/星级/频率按实测重算，统一全体系口径（如 Abstract 词数、Conclusion 词数、连接词排序只允许一个权威数值，优先 quantitative-baseline 或 style-profile）；
- **P2 约束与边界**：为全部检查清单补 ✅硬约束/💡软约束/❌禁止 分级；补「何时询问用户/何时停止/数据缺失降级」条款；补润色深度 light/moderate/deep 的能改/不能改清单；为 reviewer 每条检查项补严重性映射与判定方法；
- **P3 查漏补缺与灵活度**：补语料高频句式/术语/结构变体；补 paper_type/章节变体适配分支；reviewer 报告模板补「依据」字段并强制填写。

**每文件修改后自检**：
- [ ] 全部统计声明可溯源且口径注明
- [ ] 每条规则有 ✅/💡/❌ 分级
- [ ] 判断边界条款存在（询问/停止/降级）
- [ ] 与共享层数值、术语、句式无冲突
- [ ] 来源等级标注完整（语料实测/课题组规范/外部通用知识）

### 阶段 D：验证
1. **抽样回测**：从语料抽取 3-5 篇真实论文片段，用优化后的模板/清单跑一遍，确认模板可复用、清单可判定、无全数误判项（如词数区间必须覆盖语料真实值）；
2. **交叉一致性检查**：全文检索关键数值与术语（词数区间、we 密度、连接词排序、TABLE 编号规则、时态规则），确认四个技能 + 共享层完全一致；
3. **元数据检查**：版本号、引用路径（../ieee-mg-share/...）、manifest.yaml 的 axes/fragments/load_rules 与实际文件一致。

**输出**：`验证报告.md`，含回测结果与一致性检查表。

### 阶段 E：发布
1. 质量审查（人工或 review 工具）通过前，改动仅存在于 dev 副本；
2. 审查通过后，将 dev 副本整体复制覆盖 `skills/` 对应目录（git 历史保留旧版本）；
3. 同步更新 `skills.sh.json`、`README.md` 中的版本/描述信息；
4. git commit（信息含版本号与变更摘要）。

### 说明与使用建议

- 本 Prompt v2.0 与 v1.0 的差异：新增**第二轮蒸馏流程**（诊断→复核→优化→验证→发布）、**质量维度定义**（约束程度/思考深度/判断边界/灵活程度/可溯源性/交叉一致性）、**来源等级标注规则**（语料实测/课题组规范/外部通用知识）与**反幻觉强制规则**（断言先验证、口径注明、缺失章节禁编造）。
- 如果只想对单个技能做局部优化，可只取阶段 A-C 对目标技能执行；如果语料新增论文，先执行第一轮阶段 0-3 更新共享层，再进入第二轮。
- 建议将本流程与 `sandbox/dev/` 下的差距诊断报告配合使用：诊断报告可作阶段 A 的初始输入，避免重复扫描。

这个两轮框架兼顾了**归纳（语料蒸馏）**与**演绎（规则落地）**，并加入**审计闭环（复核→验证→发布）**，确保每一次技能升级都是数据驱动、可溯源、可回滚的。祝你蒸馏成功！
